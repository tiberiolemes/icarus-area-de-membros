# Segurança / Security

Não abra issue público com tokens, senhas, dados pessoais ou detalhes que exponham uma instalação. Use **Report a vulnerability** do GitHub quando disponível; caso contrário, solicite canal privado ao mantenedor sem divulgar a falha publicamente.

Informe versão/commit, fluxo, perfil mínimo, reprodução sintética e impacto demonstrado. Não teste instalações de terceiros nem faça cobranças para reproduzir uma falha.

`service_role` é segredo administrativo e nunca pertence ao frontend. URLs privadas assinadas são credenciais temporárias, sem lugar em logs ou issues.

Software fornecido sem garantia, conforme MIT. Testes locais não substituem configuração e homologação da instalação em produção.
